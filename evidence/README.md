# Evidence

This folder holds proof from real runs on NEAR testnet and Ethereum Sepolia. Nothing in it is
generated by the build or by unit tests, and nothing here is synthetic.

**Current state: this folder contains no chain data yet.** The contract has not been deployed, so no
evidence run has happened. Files appear below only after the builder runs the steps in this file and
commits the output. If a file is not listed in the table at the bottom, it does not exist.

## What goes here

| Path | What it is | Produced by |
|---|---|---|
| `checks.log` | One JSON line per live capability-check verdict (PASS or FAIL, with the evidence the check collected). Offline self-tests and unreachable endpoints are not recorded. | `pnpm --filter checks check:1` ... `check:6` (see `checks/README.md`) |
| `sig-<tx_hash>.json` | The MPC response from a real `sign` call: latency, gas per receipt, `big_r`, `s`, `recovery_id`. | `pnpm --filter checks check:2 -- --parse <tx_hash>` |
| `e2e-<timestamp>.json` | Sepolia transaction hashes and receipts for transfers the contract signed, plus the clean-check verdict afterwards. | `pnpm --filter checks check:5` |
| `snapshots/token-<id>.json` | A saved view of one wallet: contract state, signature log, Sepolia nonces and balance at capture time. `make verify` re-checks every file here offline. | `make snapshot TOKEN=<id>` |
| `access-keys.txt` | The `view_access_key_list` output for the contract account after its full-access keys were deleted. Proves the code cannot change. | deploy runbook in the README, section 14 |

Files in `snapshots/` that the CLI wrote have `"synthetic": false`. The synthetic test fixtures live
in `packages/cleancheck/test/fixtures/`, not here.

## How `make verify` uses this folder

`make verify` runs `handover verify` over every `snapshots/*.json` and over the synthetic fixtures.
A real snapshot is expected to be `clean` unless it has an `"expect"` field. If you commit a snapshot
that shows another verdict on purpose (for example a `dirty` wallet captured during the demo), add
`"expect": "dirty"` to it, otherwise `make verify` reports a mismatch and fails.

If `snapshots/` holds no `.json` file, `make verify` prints "No real snapshot committed yet" and
verifies the synthetic fixtures only.

## How to produce the evidence

Prerequisites: a funded NEAR testnet account, Sepolia ETH from a faucet, `.env` filled from
`.env.example`, and the contract deployed (README section 14).

```bash
# 1. Capability checks (live). Each appends to evidence/checks.log on a live verdict.
pnpm --filter checks check:1 -- 0xYourSepoliaAddress
pnpm --filter checks check:6 -- --address 0xYourSepoliaAddress
pnpm --filter checks check:2 -- --parse <tx_hash_of_probe_call>     # writes sig-<tx_hash>.json
pnpm --filter checks check:3 -- <contract_account> handover-0 --sig evidence/sig-<tx_hash>.json

# 2. Full run through the deployed contract: mint, request_transfer (README section 14),
#    fund the derived address, then:
pnpm --filter checks check:5                                         # writes e2e-<timestamp>.json

# 3. Wallet snapshots at the interesting moments (before listing, after listing, after the sale).
make snapshot TOKEN=0

# 4. After the final deploy: delete the full-access keys, then save the key list.
curl -s "$NEAR_RPC" -H 'content-type: application/json' -d \
  '{"jsonrpc":"2.0","id":1,"method":"query","params":{"request_type":"view_access_key_list","finality":"final","account_id":"<contract_account>"}}' \
  > evidence/access-keys.txt
```

Note that the root `.gitignore` ignores `*.log` but re-includes `evidence/*.log`, so `checks.log` can
be committed. Review every file for secrets before committing (the scripts never write private keys).
