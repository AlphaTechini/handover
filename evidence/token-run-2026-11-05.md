# Token run, 2026-11-05: the wallet's tokens move with the NFT

This run proves the token side of the contract on NEAR testnet and Ethereum Sepolia. Besides plain ETH
transfers, `request_token_transfer` encodes and signs exactly three token calls from the wallet:
ERC-20 `transfer`, ERC-721 `safeTransferFrom(wallet, to, id)` and ERC-1155
`safeTransferFrom(wallet, to, id, amount, "")`. It never builds `approve`, `setApprovalForAll`,
`permit` or any other call.

**Step 16 was an app bug, not a contract fault.** The sweep read the ETH balance from an RPC node one
block behind, so it asked for 0.0000000000011 ETH more than the wallet held after the last NFT
transfer's fee. The contract had already logged the signed transaction, which is exactly what the
clean check is for: the wallet showed the pending signature, and once the shortfall was topped up,
anyone could broadcast the logged transaction. The app now reads the balance at the block of the last
mined transfer ([`SweepForm.svelte`](../web/src/lib/ui/SweepForm.svelte),
[`eth.ts`](../web/src/lib/chain/eth.ts) `getBalance`).
